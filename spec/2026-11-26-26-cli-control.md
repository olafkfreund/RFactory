# Spec: `rfactory` CLI, slice A: sign in, read, join and leave

## Design

A new `rfactory` command (`core/bin/rfactory.js`, registered in `core/package.json`) talks to the same HTTP endpoints behind `oauth2-proxy` that the web page uses. Slice A covers device sign-in and sign-out, every read route, `join` and `leave`, machine-readable output, and distinct exit codes. `core/bin/rfactory-standup.js` is left unchanged.

### 1. Sign-in and proxy path (Decisions 1, 3, 4)

The CLI signs in as a person using OAuth 2.0 Device Authorization Grant (RFC 8628) against Keycloak and sends the resulting JWT as `Authorization: Bearer <token>` to `oauth2-proxy`.

- **What was checked:**
  - `https://keycloak.freundcloud.org.uk/realms/factory/.well-known/openid-configuration` advertises `urn:ietf:params:oauth:grant-type:device_code` at `https://keycloak.freundcloud.org.uk/realms/factory/protocol/openid-connect/auth/device`, token endpoint `https://keycloak.freundcloud.org.uk/realms/factory/protocol/openid-connect/token`, and `email` in `scopes_supported` and `claims_supported`.
  - `deploy/pod.sh:18`, `factory-gitops/apps/cfactory-auth/manifests/manifests.yaml:52`, and `factory-gitops/apps/rfactory/manifests/manifests.yaml:152` (`origin/main`) all pin `quay.io/oauth2-proxy/oauth2-proxy:v7.7.0`.
  - `factory-gitops/apps/rfactory/manifests/manifests.yaml:28-44,160-166` (`origin/main`) configures client `rfactory`, `issuerURL`, explicit `jwksURL`, `emailClaim: email`, `audienceClaims: [aud]`, and `X-Forwarded-Email` injection, without `--skip-jwt-bearer-tokens=true`. `cfactory-auth` already uses `--skip-jwt-bearer-tokens=true` (`manifests.yaml:84`) with `oidcConfig.extraAudiences` (`alpha-config.yaml:79`) for its CLI/editor client (`factory-vscode`).
- **What still needs live verification before building (Decision 1 gate):**
  - The live Keycloak client (`rfactory` / new `rfactory-cli`) administrative settings and a real issued device-flow token's `aud` and `email` claims have not been inspected yet.
- **Required Keycloak and proxy setup (outside `web/server.js`):**
  - Create a public Keycloak client `rfactory-cli` in realm `factory` with Device Authorization Grant enabled, no client secret (so the web client's secret in `deploy/oauth2-proxy.yaml:17` is never given to the CLI), and an audience mapper adding `rfactory`.
  - Add `--skip-jwt-bearer-tokens=true` to `deploy/pod.sh:141-144` and to `factory-gitops/apps/rfactory/manifests/manifests.yaml:160-166`. `oauth2-proxy` verifies the bearer JWT against `issuerURL`, `audienceClaims: [aud]` (`deploy/oauth2-proxy.yaml:20-22`, plus explicit `jwksURL` in `factory-gitops`), then injects `X-Forwarded-Email` from the `email` claim (`deploy/oauth2-proxy.yaml:25-28`).
- **`web/server.js` needs no auth change for slice A.** `web/server.js:161-163` reads `req.headers['x-forwarded-email']` and checks `roles.has(email, 'member')`. None of slice A's routes check `x-rfactory-action` or `Origin`; only action approvals (`web/server.js:210-213` inline), share/investigation approvals and stops (`:229` via `sameOrigin` at `:69-72`), profile mutations (`:249`), and desktop POST mutations (`web/desktop-routes.js:140`) do.
- **Local session storage:**
  - `rfactory login [--url <base-url>]` (defaulting to `RFACTORY_URL` or `https://rfactory.freundcloud.org.uk`) discovers endpoints from `<issuer>/.well-known/openid-configuration` (default issuer `https://keycloak.freundcloud.org.uk/realms/factory`), requests a device code with `scope=openid email`, prints the verification URL and user code to stderr, and polls the token endpoint until approved or timed out.
  - The session file is stored at `${XDG_CONFIG_HOME:-~/.config}/rfactory/session.json` with directory mode `0700` and file mode `0600`. It holds `{ url, issuer, client_id, access_token, expires_at }` (no refresh token in slice A, per Decision 3: the sign-in lasts as long as the provider's token allows).
  - Tokens are never printed, logged, or accepted via CLI flags or environment variables.
  - `rfactory logout` deletes `session.json` (Decision 4).

### 2. Commands and HTTP mapping (Decisions 2, 5–10)

All commands use Node 22's built-in `fetch` (`core/package.json:6` requires `node >= 22`), so no new npm dependencies are added. Every request sends `Authorization: Bearer <access_token>` and `Accept: application/json` (and `redirect: 'manual'` so a proxy `302` to login is caught as unauthenticated rather than followed).

Every project-scoped deployment (`projects: true` in `GET /api/config`, `web/server.js:187`) requires `--project <id-or-slug>` (or `RFACTORY_PROJECT`). Deployments without projects (`projects: false`) are refused in slice A (Decision 7). If `--project` matches an id in `GET /api/projects` (`web/server.js:167`), that id is used; otherwise the CLI resolves it via `GET /api/projects/resolve?slug=<slug>` (`web/server.js:138-143`, `:167-170`).

| Command | HTTP call(s) | Behaviour and notes |
| --- | --- | --- |
| `rfactory login` | OIDC device + token endpoints | Interactive device sign-in; writes mode-`0600` `session.json`. |
| `rfactory logout` | none | Removes `session.json`. |
| `rfactory status` | `GET /api/config`, `GET /api/call/status` | Shows server `commit`, `projects`, `listen`, `sttConfigured`, and current call `running`, `starting`, `generation`, `project` (`web/server.js:187`, `:263-265`; `web/call.js:612-614`). |
| `rfactory projects` | `GET /api/projects` | Lists allowed projects (`id`, `slug`, `name`, `repositories`; `web/server.js:116`, `:128-135`, `:167`). |
| `rfactory standup --project <p>` | `POST /api/standup?project=<id>` | Triggers standup summary and prints counts, unknown items, freshness, and headline (`web/server.js:145-158`, `:193-200`). |
| `rfactory review --project <p> [card_key]` | `GET /api/review?project=<id>` or `GET /api/review/<card_key>?project=<id>` | Shows project review or single card review (`web/server.js:172-186`). |
| `rfactory actions --project <p>` | `GET /api/actions?project=<id>` | Lists `pending`, `history`, and `can_approve` (`web/server.js:202-207`; `web/actions.js:174-177`). Read-only in slice A (Decision 2). |
| `rfactory shares --project <p>` | `GET /api/shares?project=<id>` | Lists `pending`, `running`, `history`, `can_approve` (`web/server.js:202-206`, `:223-224`; `web/shares.js:263-268`). |
| `rfactory investigations --project <p>` | `GET /api/investigations?project=<id>` | Lists `pending`, `running`, `active`, `history`, `can_approve` (`web/server.js:202-206`, `:223-224`; `web/investigations.js:398-400`). |
| `rfactory join --project <p> [--listen auto\|platform\|audio] <link>` | `POST /api/call` | Sends `{ link, listen, project_id }`; succeeds on `202 { ok: true }` (Decision 9; `web/server.js:267-285`). |
| `rfactory leave --project <p>` | `GET /api/call/status`, `DELETE /api/call` | Checks `status.running && status.project?.id === id` (refuses locally with exit `4` if idle or another project's call), then sends `DELETE /api/call` with `{ generation: status.generation }` (Decision 8; `web/server.js:287-297`, `web/public/app.js:679-683,714`). |
| `rfactory heard --project <p>` | `GET /api/call/events?project=<id>` | Streams SSE `data:` events (`web/server.js:299-317`, `web/call.js:614`). Closes on `idle`, `busy`, or `ended`, or on a client-side timer when `session.expires_at` is reached (exit `3`). Earlier `question`/`answer` events are not replayed (`web/call.js:58-69,614`). |

### 3. Output, terminal safety, and exit codes

- **Machine-readable output:** `--json` prints one JSON document to stdout for request/response commands, or newline-delimited JSON (one allowlisted event object per line) for `rfactory heard`.
- **Page-content limit for `heard` (Decision 5):** `web/server.js:299-316` forwards raw call events, including `roster` (`web/call.js:510-512`, which can carry a participant's `name`). Because the member page (`web/public/app.js:610-648`) does not render `roster`, `rfactory heard` drops `roster` and any unknown event types in **both** human and `--json` modes, printing only the events and fields the member page renders:
  - Lifecycle: `state` (`state`, `code`), `idle`, `busy` (`project`), `ended`.
  - Call status: `mic` (`muted`), `hearing` (`state`, `notConfigured`), `voice` (`voice`), `greeting` (`result`), `limits` (`exhausted`, `spent_usd`, `budget_usd`, `answer_seconds`, `lookups_per_question`, `github`).
  - Call content: `question` (`speaker`, `kind`, `text`), `answer` (`text`, `sources`, `snapshot`), `log` (`message`).
  - Work updates: `action-pending`, `action-updated`, `share-*`, `investigation-updated` (same public fields the page renders).
- **Untrusted text:** All server-supplied strings printed in human mode (card titles, standup text, `question`/`answer` text, error messages) are stripped of C0/C1 control characters and ANSI/OSC escape sequences (preserving `\n` and `\t` only where safe) so terminal state cannot be hijacked.
- **Exit codes:**
  - `0`: success.
  - `2`: invalid CLI usage or missing required flags (matches `core/bin/rfactory-standup.js:25`).
  - `3`: not signed in, expired local session (including `expires_at` reached during `heard`), proxy `401`/`302` login redirect, or `403` (`forbidden`, `project-not-allowed`).
  - `4`: server refused the request (`400`, `404`, `409` such as `busy`, `starting`, `stale-generation`, or `projects: false` deployment).
  - `1`: network failure, `5xx`, or unexpected response.

### 4. Deferred beyond slice A (Decisions 2, 10, 11)

- **Slice B:** `approve`, `reject`, and `stop` for actions, shares, and investigations. Requires its own intent, waits until slice A's sign-in has been in use, and changes #28's approval rule to "on the signed-in page or the signed-in CLI" (revisiting `sameOrigin` and `x-rfactory-action` checks in `web/server.js:69-72`, `:210-213`, `:229`).
- **Slice C:** starting an investigation or proposing an action from the CLI (requires new HTTP routes shared with #27).
- **Slice D:** call history / listing past calls (currently discarded after each call per #28).
- **Unattended / service-account auth:** token refresh or non-interactive credentials (Decision 3).

## Alternatives rejected

- **Extending `core/bin/rfactory-standup.js` with HTTP subcommands:** Rejected by Decision 6. `rfactory-standup.js` loads a local scope file (`core/bin/rfactory-standup.js:30-55`) and calls CFactory and the brain directly (`:125-129`); keeping `rfactory` separate avoids mixing local-scope and remote-server modes and keeps bench/test callers untouched.
- **Reusing the web client's `rfactory` secret or passing `X-Forwarded-Email` directly:** Rejected by the intent's security constraints. `web/server.js:434` binds `127.0.0.1` behind `oauth2-proxy` (`deploy/oauth2-proxy.yaml:4-8`); the CLI must authenticate through Keycloak and never hold the confidential web client secret.
- **Polling or waiting inside `join` until the bot enters the meeting:** Rejected by Decision 9. `POST /api/call` is asynchronous (`202 { ok: true }`); `join` returns on acceptance and the user or script follows with `status` or `heard`.

## Risks

- **Keycloak audience mismatch on bearer tokens:** `oauth2-proxy` checks `audienceClaims: [aud]` (`deploy/oauth2-proxy.yaml:22`). If the `rfactory-cli` Keycloak client issues tokens whose `aud` is `account` instead of `rfactory`, `oauth2-proxy` will reject every CLI request with `401`/`302`. **Mitigation:** verify a real issued JWT's `aud` and `email` claims and configure the Keycloak audience mapper before implementation.
- **No refresh in slice A:** Because slice A stores only the access token (Decision 3), a cron job or an open `rfactory heard` stream will stop once `expires_at` is reached. Because `web/server.js:160-163,299-317` authenticates SSE only at connection time, `rfactory heard` enforces `expires_at` with a client-side timer, closes the stream, and exits `3` with a message to re-run `rfactory login`; unattended refresh is deferred.
- **`GET /api/call/status` when calls are disabled:** `web/server.js:263` only registers `/api/call/status` when `allowed && call` is truthy; when `RFACTORY_CALLS` is unset, it returns `404`. **Mitigation:** `rfactory status` treats `404` on `/api/call/status` as "calls disabled" while still reporting `/api/config`.
- **Server restart resets `call.generation`:** Accepted by Decision 8 (`web/call.js:62`). `rfactory leave` mitigates targeting the wrong call by fetching `/api/call/status` and verifying `status.project?.id` immediately before `DELETE /api/call`.

## Verification

- **Pre-build live verification (Decision 1 gate, before any implementation):**
  - Inspect the live Keycloak client (`rfactory` / new `rfactory-cli`) administrative settings and obtain a real device-flow token; verify its `aud` and `email` claims match `oauth2-proxy` `v7.7.0`'s `jwksURL`, `issuerURL`, `audienceClaims`, and `X-Forwarded-Email` config.
- **Unit and integration tests (`node --test` in `core/`):**
  - Argument parsing and exit codes (`0`, `1`, `2`, `3`, `4`) for every subcommand.
  - Device flow polling (`authorization_pending`, `slow_down`, success, timeout) against a local mock OIDC server, verifying `session.json` permissions (`0600`) and that tokens never appear in stdout/stderr.
  - HTTP client tests against a real `createApp(...)` instance (`web/server.js:96`) behind a mock auth proxy: project resolution by id and slug, refusal when `projects: false`, `status`, `standup`, `review`, `actions`/`shares`/`investigations` read lists, `join` (`202`, `409 busy`, `400 bad-link`), `leave` (matching project + generation, wrong project refused locally, `409 stale-generation`), `heard` SSE streaming (clean exit on `ended`/`idle`/`busy`, client-side exit `3` when `expires_at` is reached mid-stream, and `roster` event filtering in both human and `--json` modes), and ANSI escape-sequence stripping on untrusted text.
  - Regression check: existing `core/test/cli.test.js` continues to pass unchanged.
- **Post-setup live CLI smoke test (only after Keycloak client and `deploy/pod.sh` / `factory-gitops` proxy update are in place, with owner OK):**
  - Run `rfactory login`, `rfactory projects`, `rfactory status`, and `rfactory standup --project <slug> --json` once against the running pod/cluster, and confirm `rfactory logout` removes `session.json` and subsequent commands exit `3`.

## Decisions (2026-11-28)

1. **Client ID and audience configuration in Keycloak:** Use a public client `rfactory-cli` with an audience mapper adding `rfactory`, so `deploy/oauth2-proxy.yaml` needs only `--skip-jwt-bearer-tokens=true` on the proxy flags and no extra audience list.
2. **Default base URL for `rfactory`:** Default to `https://rfactory.freundcloud.org.uk` and allow `--url` or `RFACTORY_URL` to override it for `http://127.0.0.1:4180` (`deploy/pod.sh:145`).
