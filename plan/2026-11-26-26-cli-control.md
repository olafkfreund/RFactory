# Plan: `rfactory` CLI, slice A: sign in, read, join and leave

Add a standalone `rfactory` CLI (`core/bin/rfactory.js`, registered in `core/package.json`) using Node 22's built-in `fetch` (`core/package.json:6`, zero new dependencies). Leave `core/bin/rfactory-standup.js` unchanged (Decision 6).

Approved spec decisions carried over:
- **Sign-in & proxy (Decisions 1, 3, 4; 2026-11-28 Decision 1):** Public Keycloak client `rfactory-cli` in realm `factory` with Device Authorization Grant enabled, no client secret (never share `deploy/oauth2-proxy.yaml:17`'s `clientSecretFile` secret), and an audience mapper adding `rfactory`. Add `--skip-jwt-bearer-tokens=true` to `deploy/pod.sh:141-144` and `factory-gitops/apps/rfactory/manifests/manifests.yaml:160-166` (`oauth2-proxy` `v7.7.0` pinned at `deploy/pod.sh:18`). No `web/server.js` auth changes (`web/server.js:161-163` trusts `x-forwarded-email` and checks `roles.has(email, 'member')`).
- **Base URL & target origin binding (2026-11-28 Decision 2):** Default to `https://rfactory.freundcloud.org.uk`; override with `--url <base-url>` or `RFACTORY_URL` (e.g. `http://127.0.0.1:4180` for `deploy/pod.sh:145`). Allow cleartext `http://` only for loopback hosts (`127.0.0.1`, `localhost`, `[::1]`); refuse non-loopback `http://` URLs before sending any request. Before attaching `Authorization: Bearer`, verify the resolved target URL's origin matches `new URL(session.url).origin`; if it differs, send no token and exit `3` instructing the user to run `rfactory login --url <target-url>`.
- **Session storage (Decisions 3, 4):** Store `{ url, issuer, client_id, access_token, expires_at }` in `${XDG_CONFIG_HOME:-~/.config}/rfactory/session.json` (dir `0700`, file `0600`). `login` prints the verification URL and `user_code` to stderr. No refresh token in slice A. Never print, log, or accept tokens via CLI flags, command arguments, or env vars. `rfactory logout` deletes `session.json`.
- **Project scope (Decision 7):** Project-scoped deployments (`projects: true` in `GET /api/config`, `web/server.js:187`) require `--project <id-or-slug>` (or `RFACTORY_PROJECT`) for `standup`, `review`, `actions`, `shares`, `investigations`, `join`, `leave`, and `heard`. `login`, `logout`, `status`, and `projects` do not require `--project`. Refuse `projects: false` deployments with exit `4`. Match `--project` against `GET /api/projects` (`web/server.js:167`) ids first, else resolve via `GET /api/projects/resolve?slug=<slug>` (`web/server.js:138-143`, `:167-170`).
- **Commands & read fields (Decisions 2, 8, 9):**
  - `login [--url <base-url>]`, `logout`
  - `status`: `GET /api/config` (`commit`, `projects`, `listen`, `sttConfigured`) + `GET /api/call/status` (`running`, `starting`, `generation`, `project`; treat `404` as calls disabled per `web/server.js:263`).
  - `projects`: `GET /api/projects` (`id`, `slug`, `name`, `repositories`).
  - `standup --project <p>`: `POST /api/standup?project=<id>` (counts, unknown items, freshness, headline).
  - `review --project <p> [card_key]`: `GET /api/review?project=<id>` or `GET /api/review/<card_key>?project=<id>`.
  - `actions --project <p>`: `GET /api/actions?project=<id>` (`pending`, `history`, `can_approve`; read-only in slice A).
  - `shares --project <p>`: `GET /api/shares?project=<id>` (`pending`, `running`, `history`, `can_approve`).
  - `investigations --project <p>`: `GET /api/investigations?project=<id>` (`pending`, `running`, `active`, `history`, `can_approve`).
  - `join --project <p> [--listen auto|platform|audio] <link>`: `POST /api/call` with `{ link, listen, project_id }`; succeeds on `202 { ok: true }` without polling (`web/server.js:267-285`).
  - `leave --project <p>`: fetch `GET /api/call/status`, refuse locally with exit `4` (without sending `DELETE`) unless `status.running && status.project?.id === id`, then send `DELETE /api/call` with `{ generation: status.generation }` (`web/server.js:287-297`, `web/public/app.js:679-683,714`).
  - `heard --project <p>`: stream SSE from `GET /api/call/events?project=<id>` (`web/server.js:299-317`). Earlier `question`/`answer` events are not replayed. Close on `idle`, `busy`, or `ended` (`web/public/app.js:691-699`). Enforce `session.expires_at` with a client-side timer, close the stream, print a re-login message (`rfactory login`), and exit `3`.
- **Deferred beyond slice A (Decisions 2, 10, 11):** Slice B (`approve`/`reject`/`stop`), Slice C (starting investigations / proposing actions), Slice D (call history / listing past calls), and unattended token refresh remain out of scope.
- **Output, allowlist & exit codes (Decision 5):** `--json` prints one JSON object (or NDJSON lines for `heard`). Drop `roster` (`web/call.js:510-512`), unknown event types, and unallowlisted nested fields in **both** human and `--json` modes, projecting only what `web/public/app.js:610-648,691-699` renders:
  - Lifecycle: `state` (`state`, `code`), `idle`, `busy` (`project`), `ended`.
  - Call status: `mic` (`muted`), `hearing` (`state`, `notConfigured`), `voice` (`voice`), `greeting` (`result`), `limits` (`exhausted`, `spent_usd`, `budget_usd`, `answer_seconds`, `lookups_per_question`, `github`).
  - Call content: `question` (`speaker`, `kind`, `text`), `answer` (`text`, `sources`: `[{ kind, ref, title }]`, `snapshot`: `{ items, unknown, fetched_at, newest_update }`), `log` (`message`).
  - Work updates: `action-pending`, `action-updated` (`action`: `{ id, action, args, card_key, description, effects: { text }, proposed_by, state, expires_at, detail }`); `share-pending`, `share-updated`, `share-unavailable` (`share`: `{ id, view, state, project, approval_text, reason, stale, as_of }`, `web/public/app.js:451`, `web/shares.js:37,93,118,125,160,187`); `investigation-updated` (`investigation`: `{ id, state, reason, stale, repo, sha, request, approval_text, limits: { minutes, tokens, turns }, proposed_by, test_sentences, report: { findings, refs: [{ file, line }] } }`).
  - Human-mode sanitization: strip C0/C1 control characters and ANSI/OSC escape sequences from all server-supplied strings, preserving `\n` and `\t` only where safe (multi-line text fields).
  - Exit codes: `0` ok, `1` network/`5xx`/unexpected, `2` usage (`core/bin/rfactory-standup.js:25`), `3` auth/`401`/`302`/`403`/expired session/origin mismatch, `4` server refusal (`400`/`404`/`409`/`projects: false`/local `leave` guard).

## Deviations

- Step 2 honors `XDG_CONFIG_HOME` only when absolute, requires the session file to be owned by the current UID, and accepts device verification URLs only on the issuer's origin.
- Step 3 checks call status before resolving a project for `leave`. An exact match to the running project ID bypasses the catalog, while other input still uses ID-first then slug resolution. The delete still names the generation observed in call status.
- Steps 3 and 4 treat a closed stdout pipe as successful consumer cancellation and close the event stream. Human output omits absent standup fields.
- Step 4 also records the executable in the core and web npm lockfiles so clean web installs link it.
